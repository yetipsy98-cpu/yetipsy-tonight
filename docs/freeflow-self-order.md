# Amba FreeFlow 自助点单

## 现场流程

1. Owner 在 POS → 管理 → 商品与套餐 → **FreeFlow 设置** 新建菜单，选择指定饮品、时段及可选日期范围。GPS 使用服务铃现有的经纬度和半径。
2. 扫 Amba Pass，确认实际男女人数，按原流程挂单或结账。
3. Amba 挂单后，或实际结账成功后，Cashier 会收到本单菜单选择提示；选好 Owner 菜单后开放绑定，桌号可留空并由 Cashier 稍后补填。已有场次不会重复询问菜单。
4. 所有有效员工都可从该订单的 **FreeFlow · 发码 / 绑定** 展示两分钟有效的绑定 QR，或扫描顾客动态会员码绑定。Waiter 不能代选菜单或修改资格管理设置。一个不同会员占一个人数名额；重复扫不重复占位；关闭会员资格不释放名额给其他人。
5. 顾客在会员首页或「我的」打开 **FreeFlow · 自助点单**。场内定位通过、资格及时间有效时可选一杯，直接进入 KDS。
6. KDS 确认出品后才解锁下一杯；取消须由 Cashier / Owner 填原因，取消不计杯数。仅独立 Cashier 账号播报。
7. Cashier / Owner 可管理个人与整组的暂停、恢复和关闭，修改整组桌号，按营业日查看个人、整组及各酒款统计。每位顾客只看到自己的总杯数、酒款数量、当前待出品状态、资格与截止时间，看不到下单／出品时间。

## 行为边界

- 配套是原 Amba POS 销售，逐杯请求仅作为出品，不生成额外销售、付款或积分。
- 开通时根据 Amba 订单营业日、Owner 菜单时间计算时段；结束时间小于或等于开始时间则跨至次日。修改菜单时段只影响之后新开的场次，酒款和菜单启用状态即时生效。
- 桌号仅 Cashier / Owner 设置；修改后顾客页面及之后的新杯单采用新桌号，已提交杯单保留原桌号。
- 到期、暂停或关闭只阻止新杯单，已有 KDS 请求保留。订单被取消／退款时也禁止新绑定及新杯单。
- 数据库按会员串行化下单，并以唯一索引保证一人只有一杯待出品；同请求重试返回原杯单。
- 共用绑定码按有效人数限制名额，有效两分钟，刷新后旧码立即失效。
- records 重置的同一次 TRUNCATE 包含 FreeFlow 杯单、绑定和场次，保留菜单设置；catalog 重置随商品删除清理菜单商品映射。禁止对生产执行真实重置测试。

## 访客模式

- 未登录顾客扫描已付／已挂单且选好菜单的 FreeFlow 码后，先选择「登录」或「访客访问」，同次绑定不重复询问；访客不会创建 Auth 或会员账号。
- 现有会员沿用会员绑定。浏览器已有访客资格时优先续用该资格，避免登录或重扫后重复占人数。
- 同一浏览器保存不出现在网址中的随机凭证；后台只保存哈希。刷新、关闭后重开不增加名额，和会员共用实际配套人数上限。
- 访客按 Owner GPS 开关检查场地定位，并始终检查时间和资格；一次一杯，KDS 出品后解锁。顾客看不到每杯下单／出品时间。
- Cashier / Owner 在 FreeFlow 名单的访客行点击「恢复访客设备」，让新设备扫两分钟有效恢复码。原名额、已出品杯数及待出品订单保留，旧凭证立即失效。Waiter 不能签发恢复码。
- 顾客页仍没有扫描绑定入口或流程说明。访客首页提供点单与可选的会员登录，不强制注册。
- guest API 只接受 bind / mine / order / restore，不开放菜单、KDS、会员奖励或员工操作。独立桥接 schema 未暴露为 Data API，原 private schema 对 anon 仍无 USAGE。
- records 重置同时清理访客凭证；不需要外部 Auth 清理。新增回归覆盖真实 anon 角色权限、混合人数上限、隔离、恢复码重放及旧凭证失效。

## 访客服务铃与 GPS 开关

- 未登录也可从服务铃按钮直接填写桌号并呼叫，刷新保留当前浏览器的请求。访客只能看和取消自己的请求，工作人员确认后不能自行取消，完成冷却后可再叫。服务铃仍固定开启，语音仍只在 Cashier 端。
- Owner 的服务铃与定位设置集中提供「服务铃 · 限场内 GPS」「FreeFlow · 限场内 GPS」两个独立开关，默认开启。关闭对应开关后，客户端不请求定位，后端跳过距离与坐标检查；两项都关闭时允许不填场地中心点。每次提交读取最新策略。
- FreeFlow 关闭 GPS 仅跳过位置限制，不改变已挂单／结账、绑定人数、菜单、有效期和单杯锁定。访客资格关闭或过期返回正常登录界面。
- 新迁移 `supabase/migrations/20261110030424_guest_service_bell_gps_switches.sql` 先于前端发布。records 重置同一事务清空服务铃请求与访客凭证，保留设置。

## 顾客界面与双语记录

- FreeFlow 酒单、访问方式选择、访客首页和记录页统一深绿／暖金界面。中英文沿用 `yt-client-language`，点单页也可直接切换；切换保留酒款选择、当前标签和月份筛选。商品与菜单名称保持 Owner 原文。
- 记录按场次的马来西亚开始日期倒序分组，可按月份筛选，汇总已享用杯数、场次数和酒款数。卡片显示场次状态、有效时段和桌号；跨午夜显示「次日」。不读取或显示每杯下单／出品时间。
- 日期使用现有 starts_at / ends_at，无数据库变更。已出品酒款按服务器汇总显示；待出品和取消记录不加入饮用统计。

## 点单备注、访客导入与记录入口

- 每杯支持最多 160 字备注，随杯单保存到 KDS、待出品状态和历史酒款明细；相同酒款的不同备注分行汇总，仍不显示顾客每杯时间。
- 访客「我的记录」提供「保存到会员」；点击后登录／注册，接续导入至当前会员。意图保存在设备，刷新登录页或网络丢失可重试。只有真实会员身份可导入；重复导入幂等，保存成功后清理设备访客凭证。
- 原访客会员行与当前会员同一场时合并杯数，释放重复占用名额；保留更严格的关闭／暂停状态。双方都有待出杯单或占用不同有效场次时暂缓导入，提示等待出品或场次结束，避免突破单杯和单场限制。
- 访客设备凭证与恢复尝试最多有效 10 天，读取或重复绑定不续期；服务端也拒绝过期凭证。后台保存业务记录，不因设备到期删除出品数据。Cashier 显式设备恢复签发新的 10 天凭证。
- 已结束访客回到正常登录界面，同时可在有效设备期限内从「访客 FreeFlow 记录」打开历史并保存。会员「我的」始终显示自己的 FreeFlow 记录，即使没有当前资格；首页／「我的」的点单按钮只在 active 资格时显示。

## 月报 FreeFlow 汇总

- Owner 报表新增 FreeFlow 页；沿用月份／日期范围筛选。只显示已出品总杯数、个人出杯数前 5 位（会员或访客）及完整酒款出杯统计，不返回全员明细、手机号、备注或逐杯时间。
- 按 FreeFlow 场次 business_day 归属；只统计 served，跨午夜出品仍归原场次营业日，取消和待出品不计。真实已出品杯数不因之后关闭场次或退款而抹去。
- 同一会员／访客跨场次合并排名；访客导入后按会员合并，杯单不重复。相同杯数按固定身份排序取 5 位。酒款按保存的出品名称汇总。
- 网页、FreeFlow CSV 和完整 PDF 月报均包含这两项统计。FreeFlow 生产杯数独立于现有财务流水，所有业绩计算保留。Owner Limited 可看，完整 PDF 权限保持仅完整 Owner。
- 迁移 `20261111113549_freeflow_monthly_report.sql` 先于前端部署；仅新增受保护的汇总函数并扩充现有公共包装函数，不新增业务表，重置范围不变。
